# dtrack-distributed 执行顺序索引

这组笔记按**一次 run 实际发生的先后顺序**拆分，每篇附对应源码的缩写片段和解释。设计取舍看
[[s3_split_pipeline|s3_split_pipeline]]，两套代码拆分的决定看 ADR 0006，真实运行记录看
`examples/e2e/execution.txt`，计划覆盖与改进清单看 [[plan_coverage|plan_coverage]]。

## 两套代码，只在 S3 会合

| 侧 | 代码 | 跑在哪 | 需要什么 |
| --- | --- | --- | --- |
| LEFT | `src/dtrack_distributed`（CLI：`stage1` / `produce` / `fetch-report` / `doctor`，约 1.7k 行） | 本地 PC | 左侧源库访问 + work 前缀写 + report 桶读 |
| RIGHT | `databricks/dtrack_cloud` + `databricks/consumer_notebook.py` | Databricks job，启动一次 | 目标表（或 Volume）读权限 + work / report 位置 |

本地没有任何 Databricks 凭据和包；云端从不 import 本地包（`tests/test_dependencies.py` 锁定）。

                                         [[01 配置与连接档案]]      [[04 Gate 与 manifest]]    [[07 采样与统计]]        [[09 比对规则]]
                                                       [[05 S3 提交协议]]（贯穿）                                    [[10 报告]]
                                                                                                                  [[11 e2e 运行]]

## 术语

| 词 | 意思 |
| --- | --- |
| Pair | 一对要对账的左右表 |
| Partition | 规范化后的日期值，Stage 1 的对账粒度 |
| Window | 按 `vintage` 折起来的一组已过关 Partition，Stage 2 的扫描粒度 |
| Unit | `(pair, window, column)`，Stage 2 的交付粒度，一个 JSON |
| Barrier | per-pair 的过滤：只有记录数相等的 Partition 进 Stage 2 |
| Finding | 数据差异，进报告不告警 |
| Failure | 连不上、超时、代码错，要人修 |
