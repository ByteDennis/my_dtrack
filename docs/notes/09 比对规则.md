```python
def compare_statistics(*, pair, window, column, left, right):
    result = {"pair": pair, "vintage": window, "column": column}
    for name in ("n_total", "n_missing", "n_unique"):                        # 计数：整数相减
        result[f"{name}_left"], result[f"{name}_right"], result[f"{name}_diff"] = l, r, r - l
    for name in ("mean", "std", "length_avg", "length_max", "hash_sum"):     # 数值：相对容差 1e-6
        result[f"{name}_left"], result[f"{name}_right"] = left.get(name), right.get(name)
        result[f"{name}_match"] = _float_match(...)                           # None = 该侧没有这个统计
    for name in ("mean", "std"): result[f"{name}_diff"] = float(r) - float(l)
    for name in ("min_val", "max_val"):                                       # 极值：去空白后字符串相等
        result["min_match"/"max_match"] = l.strip() == r.strip()
    count_match = all(result[f"{n}_diff"] == 0 for n in ("n_total", "n_missing", "n_unique"))
    result["verdict"] = "match" if count_match and all(checks) else "diff"
```

```python
def _float_match(left, right, tolerance=1e-6):
    if left in (None, "") or right in (None, ""): return None                # 缺一侧不参与判定
    return abs(l - r) <= max(1e-9, tolerance * max(abs(l), abs(r), 1.0))
```

## 一行结果长什么样

`results/{unit_id}.json`，也是 `<pair>_compare_col.csv` 的一行：

| 字段 | 例（orders / 2026-02-01 / AMOUNT） |
| --- | --- |
| `n_total_left / right / diff` | 200 / 200 / 0 |
| `n_unique_left / right / diff` | 200 / 200 / 0 |
| `mean_left / right / match` | 237.2905 / 237.2909 / False |
| `hash_sum_left / right / match` | 1789…792 / 1792…344 / False |
| `min_match / max_match` | True / True |
| `col_type`、`right_col` | numeric、amount |
| `verdict` | diff |

结果行携带两侧原始值，所以 [[10 报告]] 不需要回读 `units/`。

## 为什么 mean 差 0.0004 也判 diff

e2e 在右侧 2026-02-05 每行 AMOUNT +0.01，28 天里改了 1 天，样本均值只挪了千分之几。相对容差
1e-6 就是为了抓这种事；`hash_sum` 同时不等，两个证据互相印证。发现只负责"问题存在"，全量确认
SQL 是后续。

## unit_id

```python
def unit_id(pair, window, column):
    digest = sha256(json.dumps([pair, window, column])).hexdigest()[:12]
    return f"{slug(pair)}--{slug(window)}--{slug(column)}--{digest}"    # orders--2026-02-01--amount--dae64eb47234
```

可读前缀 + 12 位摘要：人能看，重跑幂等，`results/` 天然去重。本地与云端的 `unit_id` 逐字节相同
（parity 测试），所以本地 `_INDEX` 里的 id 和云端 `results/` 里的 id 必然对得上。
