## 为什么两侧能独立选中同一批记录

```python
# engine/normalization.py（云端 dtrack_cloud/normalization.py 相同）
PURE_DECIMAL = re.compile(r"^-?[0-9]+\.[0-9]+$")
def collapse_decimal(text):                    # legacy 规则：只对纯小数折叠尾随零
    if not PURE_DECIMAL.match(text): return text             # '007'、'1e3' 原样保留
    return re.sub(r"\.0+$", "", re.sub(r"(\.[0-9]*[1-9])0+$", r"\1", text))   # '2.50'->'2.5', '2.0'->'2'

def normalize_value(value, family="string"):
    if value is None or not str(value).strip(): return "<<NULL>>"
    if family == "date":    return canonical_date(text)                     # '01JAN2026' == '2026-01-01'
    if family == "numeric": return collapse_decimal(text)
    return unicodedata.normalize("NFC", text).lower()                       # 'Abc' == 'abc'

def hash32(value):  return int(hashlib.md5(value.encode()).hexdigest()[:8], 16)      # 0 .. 2^32-1
def selected_fraction(values, families, threshold):
    return hash32("|".join(normalize_value(v, f) for v, f in zip(values, families))) < threshold
```

`threshold = rate × 2^32` 写在 manifest 里，两边读同一份。hash 碰撞只会让两个 key"一起选或一起不选"，
两侧仍一致；重复 key 单侧就能看出（key 列的 `n_unique` 对 `n_total`）。

## 右侧：一条 `spark.sql`，采样谓词和统计都在仓内

```python
# databricks/dtrack_cloud/targets.py
def _collapse_decimal_sql(text):                       # collapse_decimal 的 SQL 孪生（legacy _strict_num_str_collapse）
    CASE WHEN text rlike '^-?[0-9]+\\.[0-9]+$'
         THEN regexp_replace(regexp_replace(text, '(\\.[0-9]*[1-9])0+$', '$1'), '\\.0+$', '') ELSE text END
def _norm_sql(column, family):                         # 与 normalize_value 逐条对照
    numeric: coalesce(nullif(_collapse_decimal_sql(trim(cast(`c` as string))), ''), '<<NULL>>')
    date:    coalesce(date_format(cast(`c` as date), 'yyyy-MM-dd'), '<<NULL>>')
    string:  coalesce(nullif(lower(trim(cast(`c` as string))), ''), '<<NULL>>')

def _sample_predicate(manifest, window):
    composite = concat_ws('|', norm(k1), norm(k2), ...)
    fraction:  conv(substr(md5(composite), 1, 8), 16, 10) < threshold        # == hash32
    fixed:     composite IN ('a|b', ...)                                       # keys.json 里的 key

def window_statistics(manifest, window):
    where = partition_where(带洞 partition 列表, dialect="spark") AND (sample)
    SELECT count(1) AS n_total,
           count_if(`c` IS NULL) AS n_missing_0, count(DISTINCT cast(`c` as string)) AS n_unique_0,
           sum(cast(conv(substr(sha2(coalesce(cast(`c` as string),'<<NULL>>'),256),1,16),16,10) as decimal(38,0))) AS hash_sum_0,
           avg(...) / stddev_samp(...) / cast(min(...) as string) / cast(max(...) as string) / avg(length(...)) / max(length(...))
    FROM relation WHERE where
```

一个窗口一条查询，只回一行；`col_type` 由 `DESCRIBE` 的列类型决定。`strict` 时统计前先
`lower(collapse(trim()))`，pandas 侧同样是 `collapse_decimal(str(v).strip()).lower()`。

## 与 legacy 分支的对照

| legacy | 现在 |
| --- | --- |
| `_strict_normalize`：numeric 只折叠纯小数尾零、保留前导零；string `lower(trim(COMPOSE/NFC))`；空值 `<<NULL>>` | 同规则，`normalize_value` + `_norm_sql` |
| `_hash32_expr`：md5 前 8 hex → 32 位桶 | 同，`hash32` / `conv(substr(md5(..),1,8),16,10)` |
| `_hash16_expr`：md5 前 4 hex（16 位，为迁就 Oracle `STANDARD_HASH`） | 改为 sha256 前 16 hex；两侧都是自家代码，碰撞率更低 |
| 日期 key `_canonical_date_key_expr` → `YYYY-MM-DD` | 同，`canonical_date` / `date_format(cast(.. as date))` |

## strict 的含义

`customers` 配了 `strict: true`：左侧 `Gold`、右侧 `GOLD`，两侧都折成 `gold`，e2e 判 match。
不加 strict 的 `orders.STATUS` 被右侧小写化一天，n_unique 4 → 7，判 diff。
