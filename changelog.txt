pair_recon Batch reliability, smoke checks, and runtime recovery — 2026-10-27

Summary
- Added sequential batch execution and an inexpensive end-to-end smoke command.
- Added Oracle session/fetch recovery, Databricks Volume read recovery, and a cross-stage watchdog.
- Preserved both row counts for empty plans and introduced `empty`, `left_only`, and `right_only` terminal states.

Added files
- `src/pair_recon/app/cli/batch.py`: runs pairs sequentially in child processes, trusts exit codes, records elapsed time/state, and updates `batch_summary.json` after every pair.
- `src/pair_recon/app/cli/smoke.py`: checks Left, samples 100 rows with the real predicate, verifies a Volume round trip, and runs a short Right key-selection check.
- `tests/unit/flows/test_commands.py`: covers batch result parsing/classification, temporary defaults, continued execution after failures, and local CSV smoke behavior.

Modified files
- `README.md`: documents smoke/batch usage, empty-plan states, Oracle session controls, and watchdog thresholds.
- `changelog.txt`: replaces accumulated history with this single-commit summary and complete file inventory.
- `guideme.txt`: adds concise operator instructions for the new commands, recovery settings, and terminal behavior.
- `src/pair_conn_release/publish.py`: restores `core/metadata/mapping.py` to the portable runtime so the packaged CLI imports successfully.

- `src/pair_recon_left/backends/sources.py`: returns exact fetched row counts, adds sampled-key helpers and fetch progress, bounds Oracle sessions, caches LDAP DSNs, and retries session/network failures.
