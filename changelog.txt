pair_recon Reliability, diagnostics, centralized tables, and normalization controls — 2026-10-28

Summary
- Added sequential batch execution and an inexpensive end-to-end smoke command.
- Added Oracle session/fetch recovery, Databricks Volume read recovery, and a cross-stage watchdog.
- Preserved both row counts for empty plans and introduced `empty`, `left_only`, and `right_only` terminal states.
- Added protocol 4's operator-facing `config/`, `results/`, `differences/`, and `audit/` tree while isolating distributed checkpoints under `_protocol/` with no legacy markers.
- Added exact-key difference sampling; each differing vintage writes one narrow `samples.csv.gz` with `sampled_key`, `partition`, `attribute`, `side`, and `value`.
- Made `--debug` reconcile Left and Right statistics locally while keeping Right sampling and statistics computation in Databricks.
- Added the `difference_sample_rows` run option, defaulting to 1000, without invalidating reusable statistical plan units.
- Replaced separate Unity Catalog table settings with one `DBX_CATALOG_SCHEMA=catalog.schema` namespace and centrally fixed table names.
- Added the five-column `pair_recon_normalization` registry for global transforms and source-scoped synonyms, including default `strip_datetime` and enabled Oracle `3000-01-01`/`9999-12-31` sentinels; no per-rule prompt was added.
- Records the effective normalization rule list in YAML, request/config data, and every execution manifest.
- Made table-controlled normalization symmetric between Left/DuckDB and Right/Spark and removed the runtime `strict` switch.
