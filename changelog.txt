pair_recon 0.1.0 — 2026-10-18

Added
- Hadoop Left source through pyodbc and an ODBC DSN.
- UTF-8 local CSV Left source through DuckDB read_csv.
- Periodic Unity Catalog progress snapshots with run/unit counts and active worker threads.
- Optional SAS bundle generation: Left only by default, or Right/both on request.
- Interactive local CSV override in the normal run command, reusing the existing multithread statistics path.
- Local CSV Right target in the same normal run command; local Right skips Databricks job startup while retaining UC results and progress.
- Sample provenance reuse so a non-sampled counterpart applies the same deterministic predicate.
- Optional --debug behavior for Just recipes; Python failures attach ipdb.
- Concise end-to-end setup, run, SAS, CSV, progress, Outlook, and troubleshooting guide.

Changed
- Local column pulls now use named bounded worker threads visible in progress snapshots.
- Row counts apply the same deterministic sample when only one side is already sampled.
- Hadoop validation accepts query-only metadata or schema plus table.
- Just recipes avoid shell startup warnings while keeping debug opt-in.
- Live source tests cover configured Oracle, Hadoop, and CSV query/DataFrame/CSV/timing paths.
- setup/schema.sql now includes pair_recon_progress_snapshot.
- README and environment examples document the restored workflows.

Removed
- No files or capabilities were removed in this change.

Verification
- 508 unit tests pass; 12 optional tests skip.
- 9 live tests collect successfully and were not executed.
- Ruff check and format checks pass.
- Wheel and source distribution build successfully.
